# 个人学习、练习与复习网页：设计与执行计划

版本：设计稿 v1 · 调查日期：2026-09-11 · 使用者：朱志鹏

**交付范围：完成环境调查、业务规则、数据关系、持续同步方案和分阶段验收。本文不是已经实现或已经通过测试的软件。**

本文供后续执行 agent 使用。用户附件及“持续同步”补充是硬约束；本文标记为“建议默认值”的内容属于方案建议，不能冒充已获确认。没有收到用户进一步选择时，先按这些默认值制作可审查的小阶段结果。仅涉及纯笔记拆题、来源身份歧义等需要人工判定的内容暂不正式发布，不阻断其他明确题目。

## 1. 结论与实现边界

推荐做一个运行在本人电脑上的 Python 单体网页：**FastAPI + Jinja2 页面 + 少量原生 JavaScript + SQLite**。浏览器负责练习交互，后端受控调用现有 `lark-cli`，并通过一个简单 HTTP 适配器调用 Agnes。默认时区 `Asia/Shanghai`，默认仅监听 `127.0.0.1`。

先建立“持续同步 → 稳定任务 → 保存作答 → 评价/自评 → 复习轮次 → 历史”的可靠闭环，再补齐自由练习、秋招、反思和展示。持续同步、版本快照、异常保底和幂等从第一阶段进入设计，不能推迟成一次性导入之后的增强项。

飞书管理原题、参考材料和原有分类；网页管理所有学习事实和面试派生题。**题目当前内容可以更新，已经发生的学习事实不能被同步改写。**

不引入在线判题、代码执行、模型代码审查、多 Agent 运行框架、向量数据库、微服务、社交、排行榜和复杂记忆算法。开发工作可以由多个 agent 分工，但产品本身不需要多 Agent 框架。

FastAPI 官方提供 Jinja2 模板集成；这个选择使首版只需维护一套 Python 服务和一套持久化数据。它是结合个人使用规模作出的工程建议。[FastAPI 模板文档](https://fastapi.tiangolo.com/advanced/templates/)

### 2.4 模型实际是 Agnes，旧型号已弃用

本地白名单配置检查结果：

- 文件 `/path/to/GenericAgent/mykey.py:1–11` 中配置名为 `native_oai_config_agnes`，模型为 `agnes-2.0-flash`。
- Base URL 为 `https://apihub.agnes-ai.com/v1`，协议为 Chat Completions，后端 Bearer 认证。
- 本轮仅确认密钥存在，未输出密钥、未导入运行配置文件、未调用模型。
- 参考实现位于 `llmcore.py:397–423`；重试处理位于 `:360–395`。现有配置的 `connect_timeout` 与代码读取的 `timeout` 字段不一致，不能整份照搬并假定超时生效。
- 不直接复用现有 `fast_ask`，因为请求错误可能返回成普通文本；也不直接引入 GenericAgent 的 `ToolClient` / `NativeToolClient`，它们会记录完整 Prompt/Response。新服务应使用明确错误类型和脱敏日志。

截至本次官方资料核查，2.0 页面标记 Deprecated 并建议新集成迁移 2.5；价格页将 `agnes-2.5-flash` 输入/输出列为当前免费，但是否可用、计费和额度取决于账户权益，不能承诺永久免费或无限量。[2.0 官方文档](https://agnes-ai.com/en/docs/agnes-20-flash) · [2.5 官方文档](https://agnes-ai.com/en/docs/agnes-25-flash) · [当前价格](https://agnes-ai.com/en/docs/pricing)

建议默认使用同一个 Agnes provider，**先验证现有 key 对 `agnes-2.5-flash` 的免费权益和可用性，再启用正式调用**。不得自动改用付费模型。当前 Token Plan 文档列出免费/default 文本模型有效 20 RPM；应用先采用单并发、约 10 次/分钟的内部限速作为保守工程默认值，并尊重 `Retry-After`。用户同时运行 GenericAgent 可能共用账户额度。[Token Plan 官方说明](https://agnes-ai.com/en/docs/tokenplan)

### 2.5 本机已成功运行的只读命令示例

下面使用本轮真实可用的 bot 身份。实施时身份由来源配置固定，不能遇到权限错误就无提示切换身份；恢复 user 后也需重新验证。

```bash
# 指定来源：目录与稳定块锚点调查
lark-cli docs +fetch \
  --doc 'https://example.feishu.cn/wiki/demo-theory' \
  --scope outline --detail with-ids --as bot --format json

# 轻量查询当前 Docx revision
lark-cli api GET \
  '/open-apis/docx/v1/documents/demo-theory-document' \
  --as bot --format json

# 最新正文块第一页；后续把返回游标作为 page_token 放进同一 params
lark-cli api GET \
  '/open-apis/docx/v1/documents/demo-theory-document/blocks' \
  --params '{"page_size":500,"document_revision_id":-1}' \
  --as bot --format json
```

实现中用 argv 数组调用，不拼 shell 字符串。分别捕获 stdout/stderr，先核验进程状态和 `ok == true` 再读 `data`，不能按老 OpenAPI 顶层 `code == 0` 判断 CLI 成功。外层错误分类有时不准确：本轮素材权限错误被包装为 transport、表格权限错误被包装为 server_error；应结合内层授权码和信息识别，不能按网络错误无限重试，更不能判删。

### 3.2 八股样例：AdamW 显存估算

- 实际分类：`计算效率问题`，主题可额外索引为 AdamW、优化器状态、显存估算。实际目录没有一个独立的“优化器”标题，不应伪造已有模块。
- 原文问题：**“8 张 80GB 的 H100，如果用 AdamW 训练，光从显存角度看，最多能装下多少参数的模型？”**
- 主锚点：问题段落 `demo-reference-020`，位于引用块 `demo-reference-021` 内。
- 参考材料：紧随其后的 `demo-reference-022` 和 `demo-reference-023`，原文按 12 字节/参数估算约 53B，并说明没有计入激活值等其他开销。
- 这两块是原文依据，不是本计划对技术结论的独立认证。题目涉及显存是否聚合、训练状态布局等假设；评价时应暴露假设，不能把给出合理不同假设的回答机械判错。必要时将参考质量标为待核验。
- 之后正文转向矩阵乘法 FLOPs，不能把直到下一标题的所有内容都当作这道题答案。

[直达原文位置](https://example.feishu.cn/wiki/demo-theory#demo-reference-020)

### 3.3 不能统一“每个标题就是一道题”

真实反例：

- `大模型架构 > TF架构` 一节同时包含架构图、Pre/Post Norm、warmup、RMSNorm、bias、门控激活函数等笔记和疑问，不是一道有完整统一答案的题。
- `hot100 > 链表题 > 链表排序&合并k个链表` 的同一标题下包含两种题目及各自代码/截图，不能按标题机械合并成一道，也不能用第 1/第 2 段序号充当永久身份。
- “基础语法”“原理”等标题可能是资料分类，空标题和代码片段也不能自动充数。

**建议默认解析政策：**明确题干和可靠边界按已确认规则自动发现；纯笔记、复合题、答案边界不确定的内容进入候选区，展示题干草稿、分类、原文块和参考范围，首次确认后才发布。后续明确新增题不需逐题导入；只有歧义内容需要人工处理。

纯笔记改写成问题时，记录 `prompt_origin=note_adaptation` 和用户确认；只能忠实于已授权原文，不能混入模型臆造知识后自称飞书原题。面试生成的新追问始终是 `source_kind=derived`。

抽取以规则为主，模型只帮助提出边界/候选。保存 `parser_version`、边界映射和人工决定；未变区块复用结果，不能每次同步重跑模型并随机改变题目拆分。未知块保留原始数据并报告，不能静默丢掉。

图片必须分清 `source_image`、`cli_alt_unverified`、`ocr_draft`、`user_verified_transcription`。只有可靠原文或核验过的材料进入正式评价依据；OCR/视觉模型能力未实测前不假定可用。对于图片题，首版先支持原图展示与归档；不以一次 OCR 结果代替原始图片。

## 4. 产品流程和页面

### 4.1 页面范围

| 页面 | 最少需要的内容 |
|---|---|
| 今天 | 代码/八股目标、可展开模块分配、稳定任务列表、基础/追加/完成分开显示、同步状态 |
| 练习页 | 同一答题组件服务每日/自由/复习/秋招；代码按钮或八股回答框；版本固定 |
| 自由练习 | 一句话输入主题与数量，展示筛选结果、缺口及追加任务 |
| 复习库 | 在复习/已达标/历史轮次；有效次数、首末时间、来源状态、版本变化 |
| 秋招 | 主问题、多轮对话、结束当前题、集中反馈、整理追问入复习 |
| 历史 | 按日时间线、热力图、题目历史、个人反思与模型反思 |
| 题库与来源 | 同步按钮、逐来源状态、增加来源、分类、解析候选与匹配问题 |

练习页提交前默认隐藏参考答案、旧回答和反馈。仅打开题目不算完成。用户查看答案后仍允许练习，只影响有效通过资格，不增加自评档位。

### 4.2 正常闭环

1. 登记两份来源，读取并验证一小批真实题，确认解析样例。
2. 设置代码总量、八股总量及可选模块配额。
3. 点击生成：检查同步状态，在候选集合内随机抽题，一次保存当天基础计划和任务。
4. 打开任务时固定作答版本；提交时先可靠保存自评/回答，再调用评价。
5. 代码不会做自动入复习；八股评价与入库分开，只有用户点击或明确指令才入库。
6. 从任意入口再次练习，同题复用同一身份；符合当前轮次规则的通过才计有效次数。
7. 本轮至少 5 次有效通过且首末跨度严格大于 7 天，退出待复习队列，保留达标依据与历史。
8. 按天填写个人反思、生成模型反思，通过时间线和题目历史回看。

三个状态始终分开：`task completion`、`adopted assessment`、`review membership`。例如八股已提交、模型评价失败：任务已完成，评价待重试，未发生任何自动入库。

## 5. 七项业务口径：建议默认值

### 5.1 八股总量与模块联动

采用“总预算 + 可固定的模块数量 + 剩余随机”。例如总量 10，固定优化器 3、Transformer 4，则显示“其他符合条件题随机 3”。主题示例不等于当前已有分类。

- 允许只填总量；展开后才出现细分项。
- 固定配额之和不能超过总量；超过时保留输入并提示差额，阻止保存，不偷偷改任何数字。
- 每个配额模块覆盖一个来源分类子树；同一份分配禁止同时固定一个父模块和其子模块，避免重叠预算。初版常用分配默认一层即可。
- 先在各固定模块中随机、不放回抽取，再从剩余允许集合抽剩余数量；同一道题只占一个名额。
- 某固定模块不足就显示该模块缺口，不拿别的模块补固定配额。未限定模块的“剩余随机”正常抽取。
- 新分类出现时默认没有固定配额，不修改已保存设置。自动剩余随机区可覆盖新分类，但应展示实际分布。
- 分类删除、移动或 ID 重建导致已存配额失效时提示配置需要调整，不用同名新分类自动替换。

### 5.2 每日常规新旧题安排

首版从全部已发布、可用、符合题型/模块条件的飞书原题中均匀随机，历史做过的题也可以被选中；不增加新旧比例设置。排除所有仍有待完成/进行中任务的同题，并在当前批次去重。

既有复习题若自然被抽中，可按同一复习规则计通过；不因为复习积压而加量。派生题通过独立复习入口练习，默认不进入每日普通原题抽题池。

同一天基础计划生成请求幂等。修改以后每天默认目标不会改变今天已生成任务；当天额外需求走明确追加操作，首版不做自动重排。

### 5.3 主动复习如何计当天追加

- 打开复习列表、查看历史不加量；点击“开始复习”才查找/创建任务。
- 若同题已有符合本次目标复习依据的未完成任务，继续该任务，不新建。保留其原始任务来源，另记本次进入方式为复习。明确选择新版时，不能复用一个只能练旧依据的进行中任务。
- 否则建立 1 个复习追加任务，当天目标 +1。反复刷新或重复点击用同一请求 ID，不反复追加。
- 一个任务内“再答一次”保存新 attempt，但任务完成数仍为 1，不新增目标。
- 想另开一个正式任务时使用明确“再练一题”；同日有效通过仍按去重规则处理。

### 5.4 有效通过

全部练习入口使用同一规则，不只有复习页面答对才有效：

1. 作答开始时已存在该题的活动复习轮次，且本次内容所属 `review_basis_id` 与该轮一致。此时把 `review_round_id` 固定到 attempt；没有合适轮次则为空，后来的入库不回填。延迟到达的评价只能关联该作答原本绑定的轮次，不能算入后来新开的一轮。
2. 最终采用结果为通过；代码只能来自本人“会做”，八股来自模型结果或保留审计的人工修正。
3. 同题、同轮、上海自然日最多 1 次有效通过；所有实际作答仍保存。
4. 提交前已经查看答案/旧回答/讲解的该次作答不计有效通过；应用内看到这些材料后的 24 小时内重答也不计。24 小时是建议防刷默认值，不是用户既定硬约束。
5. 正常提交后才看到反馈，不撤销刚才合格的通过，只影响后续作答。应用无法知道用户是否在其他软件看过答案，应诚实描述这个边界。
6. 中途失败不删除此前有效通过，规则是累计，不是连续。入库前的历史通过不回填新轮。
7. 同一作答的模型重试/重新评价不产生新的作答或通过次数。评价修正后，按所有仍有效的记录重新计算每天最早一条合格通过、数量和首末时间；日期归属用作答提交时间，不用模型返回时间。

硬约束保持原样：

```text
eligible_to_exit =
  current_round.valid_pass_count >= 5
  AND last_valid_pass_at - first_valid_pass_at > 604800 seconds
```

达标自动退出当前待复习列表，显示“本轮复习已达标”；不称为永久掌握。仅时间过去不会凭空产生第 5 次通过，跨度取有效作答时间，不取当前时间。

已达标代码题再次不会做，自动开新轮；已达标八股题再次评价需复习，必须用户明确加入后才开新轮。旧轮次完整保留。

评价修正使既往达标失去依据时，保留当时达标事件并增加撤销事件，显示“达标依据已修正”。若没有后来的新轮且依据仍适用，代码可恢复原轮；八股已经退出后不自动恢复入库，提供“继续该轮复习”操作。若已有后续轮次，则只修正旧轮历史，不重新激活旧轮或影响当前轮。其原因是评价纠错，不是假装发生了一次新遗忘。

### 5.5 历史新题判定

首次正式提交回答或代码自评才变为“练过”。展示题目、草稿、点击打开不算；八股模型失败但回答已保存，仍算已经练过。这个事实属于稳定 `question_id`，任何同步、分类和版本变化都不能重置。

自由练习候选必须同时满足：来自飞书原题、已发布、主题相关、来源可选、没有历史提交、没有待完成任务、没有未解决身份歧义。模型临时生成的题、派生题、旧题不得补足。只看过答案但尚未提交，仍符合“未练过”的定义；有效通过另受答案暴露规则约束。

### 5.6 经典题

在题库页手动星标“经典”，初始为空。模型可建议，不直接写入该标记。飞书代码目录里的 `hot100` 可以按原分类筛选，不能等同于用户已经设置的经典星标。

### 5.7 不足、无答案与异常

- 基础请求 10 题、只能生成 8 题：保留“基础目标 10 / 已分配 8 / 缺 2”，不制造空任务、不假称目标全部完成。以后补缺需明确点击，只补缺额，不重抽原任务。
- 自由请求 3 题、找到 2 题：只追加实际 2 题，显示少 1 题及原因。失败或无结果不修改未来默认设置。
- 明确题干但参考答案不足：可练习并保存回答，评价为待核验，不自动判错/计通过；人工补充或确认参考材料也要建立独立来源标记和版本。
- 用户可纠正评价，但若参考依据本身缺失，应先明确补充/确认依据，避免误点“通过”伪装已完成可靠核验。
- 飞书失败使用最近成功缓存，模型失败保留回答并提供重试。内容来源状态、材料完整性和评价状态在界面分别显示。

## 6. 自由练习与秋招的边界

### 6.1 自由练习

输入“今天额外练 3 道优化器相关问题”后，模型只提取有约束的结构：题型、数量、主题、可选分类。后端负责验证数量、查题、判断历史新题、随机抽取和追加事务。用户原指令已授权这次追加，解析明确时不用二次确认。

首版用分类路径、题干、经验证参考文字的普通文本匹配与少量可解释的主题别名；如“优化器”可以召回 Adam/AdamW 相关材料。必要时模型只对已召回 ID 判断相关性，后端拒绝不存在的 ID，再从相关集合随机抽取。语义筛选不是让模型直接挑出固定几道题；最终抽取必须由程序随机。

现有 XML 总量适合先做本地文本索引，但可用题目总数尚未确认；先测真实主题召回率，再决定是否增加 SQLite FTS。首版不预设向量库。外部模型只接收有关题目的必要片段，不整本发送题库。

零候选时，先强制尝试本次来源刷新；同步失败则写“在截至某时间成功同步的题库中没有找到；本次更新检查失败”。解析待确认/素材缺失等原因要与“完全没有相关题”分开报告。

### 6.2 秋招练习

主问题默认在近期失败记录、活动复习题与用户星标经典题的并集中随机抽取。建议需要多题时先分约 2/3 给薄弱题，其余经典题；集合去重，某类为空时提示并从另一类补足。没有这些候选时明确提供“从原题库随机开始”，不能自行声称有经典题。

每轮围绕一题，追问根据当前回答展开。建议最多自动追问 3 次，用户可主动继续或随时结束；轮次结束再集中反馈，不先完整讲解再考讲解内容。代码仍只由用户做“会做/不会做”自评，追问可以讨论思路，但模型不能据未见代码宣称存在具体实现错误。

一道主问题创建一个追加任务；追问只增加对话记录，不增加目标、主任务完成量或同题有效通过。主问题首次有效提交即完成该任务一次，面试会话仍可继续；未回答直接结束不完成。模型后续反馈的变更以评价版本呈现。

整理不会的追问时，草稿至少含独立题干、背景、分类、核心参考要点、来源性质、主问题版本、相关对话 turn ID 和本次遗漏原因。用户明确加入后创建一个 `derived` 题目及复习轮；原会话中的表现保留为来源证据，不另造已完成任务。今后实际复习该派生题时才生成复习任务。

八股派生题必须由用户决定入库；依据不足时保留待核验，不靠模型自编答案获得有效通过。飞书同步从不对 `derived` 题做缺失或删除判断。

## 7. 持续同步：必须随首个闭环交付

### 7.1 来源登记与授权范围

初始登记两条明确文档来源，保存 wiki URL、解析后的 document_id、题型、启用状态和读取身份。外部文档 ID 是来源对象的稳定键，不能只拿用户粘贴的 URL 字符串判重。两个 Wiki 链接指向同一 document_id 时应提示已有来源。

“增加题库来源”只需粘贴文档链接、选择代码/八股、查看读取和解析预览，再启用。已登记文档内部新增题目自动参与后续同步；无需逐题导入。首版不扫描整个知识库，也不沿所有正文超链接继续抓取其他文档。

来源文档内部真正嵌入的图片/Sheet 属于其依赖材料，记录明确的依赖清单。只读取实际被引用的资源范围；不能因为嵌入了一张 Sheet 就把整个工作簿其他子表都当作题库。以后若开放目录自动发现，应先显示将登记的文档范围并取得用户明确授权，再限定父节点递归、逐页读取。

停用或移除来源仅停止以后同步/普通选题，不删除学习记录。不能把“用户停用”“源文档不可访问”“确认源题被删”混成一个状态。

### 7.2 触发与新鲜度

建议首版不用后台常驻轮询或实时事件：

| 触发 | 行为 |
|---|---|
| 点击“同步飞书” | 强制检查登记来源，读取最新块及依赖并生成差异摘要；同来源已有运行任务则复用其进度 |
| 生成每日任务前 | 最近成功检查超过 10 分钟则查询各来源最新 revision；变化则同步；失败可使用缓存，并醒目标明 |
| 自由找题前 | 对相关来源做一次轻量 revision 检查；同一次连续请求可合并，不能只依赖页面打开时缓存 |
| 准备返回“没有历史新题” | 若本次还没有成功检查，强制尝试；检查提示变更则等同步结果；没有可信元信息或解析覆盖不全时补一次全文检查，并说明剩余限制 |
| 元信息异常/不可用 | 尝试受控全文读取；仍失败时使用缓存。不能用失败的元信息请求证明没更新 |
| 新增来源/解析规则升级 | 对受影响来源完整同步，规则升级先预览拆分/身份差异 |

内嵌表格独立变化不一定改变父文档 revision，已登记依赖必须独立检查自己的版本或重新读取比较。父文档版本没变，不代表关联参考材料没变。普通外部超链接只作为来源链接，不自动抓取。

“无变化快速返回”只能在版本相对于**上次成功发布快照**未变，且无材料/分页/解析待重试、无解析器升级、无待二次确认的 `missing_pending` 时使用。否则即使 revision 不变，也要重试未完成步骤；恢复权限后才能修复上次部分同步，下一次独立检查也应让疑似删除得到完整读取验证。可保留需要人工确认的纯笔记候选，但必须继续显示其覆盖限制。

建议至少记录 `last_check_at`、`last_check_success_at`、`last_content_sync_at`、`last_complete_sync_at`、`last_error`。轻量检查确认 revision 没变，可以更新检查时间，不能伪造重新下载时间。素材缺失、解析歧义和单篇失败分别展示；“上次成功同步”应精确到来源与完成范围。

示例提示：`八股正文已同步至版本 12089；有 1 个内嵌表格和部分图片未读取。代码题库更新检查失败，正在使用 17:20 的缓存。`

### 7.3 获取、验证、比较、发布

每个来源独立执行以下流程；网络调用不能放在长数据库写事务中：

1. 建立同步运行记录，获取该来源锁，读取上次成功快照及解析器版本。
2. 查询 Docx 元信息，记录起始 revision `r_before`。若仅检查且正文、依赖均无变化，可结束为“已检查，无变化”。
3. 把最新块列表写入暂存区，`page_size=500`，始终用 `document_revision_id=-1`，按返回游标继续直到显式 `has_more=false`。保存每页成功标记、游标、块数；不把终端显示截断当作源数据。
4. 再查询元信息。若 `r_after != r_before`，这一整批不具备一致性资格，丢弃暂存发布候选并从头重试一次；仍持续变化则提示稍后再试，保留原库。**不能在同一批次中途从固定版本切换到最新版本。**
5. 若未来某读取身份已经具备合法的固定 revision 读取能力，可整批固定同一 revision；但不为此扩大到不必要的编辑权限。即便固定版本完整读完，发现来源又有新版也只能说“已同步至 r”。
6. 验证根节点、ID 唯一、children 引用、parent 关系、无环与无解释的孤立块。遍历所有容器，不只读取顶层标题。
7. 处理依赖、建立块覆盖表：每块明确属于题干/参考/分类/非题笔记/资源待处理/不支持/身份歧义之一。资源与题目边界未覆盖的部分不能默认为空。
8. 用既有绑定匹配题目，计算新增、当前内容变化、分类变化、疑似缺失和歧义。模型只给候选与说明，不直接决定历史合并或删除。
9. 校验后用短事务提交本来源可发布的题目和版本；独立发布仅限无身份歧义的变化。所有未绑定新候选先与全部已登记来源的既有题目及待删除绑定比较，有迁移可能的候选需等相关来源检查或人工确认后才能发布。未完成的相关材料保留旧可用版本或停留候选区。该来源存在未解决覆盖问题时，整体标部分同步并禁止自动删除。
10. 记录本次摘要和准确时间，释放锁。A 成功、B 失败可以分别提交，整体展示“部分成功”。崩溃在提交前不影响旧库；提交成功后重试不重复发布。

保守完整性要求：分页、结构和解析覆盖全部可信后才允许自动判断该来源题目缺失。未知题干块、模型解析失败、媒体依赖失败、身份歧义、游标循环、超出页数上限、部分读取 `<fragment>/<excerpt>`，都不能触发批量删题。

当前真实读取已经验证原生最新分页路径；分页途中改源、截断、子块缺失等故障尚未试验，必须进入自动化验收。只比较两次 `+fetch` 文本相等并不足以证明完整性。

### 7.4 题目身份：本地永久 ID + 来源绑定

应用生成永久 `question_id`。来源绑定记录 `document_id`、主锚点块、关联题干/答案块、历史锚点别名、人工确认记录和解析版本。标题、分类路径、顺序、正文哈希都只是属性或匹配信号。

按以下优先级处理：

| 观察 | 处理 |
|---|---|
| 同一主锚点仍在，题目边界对应 | 保持 question_id；标题/分类/顺序可更新 |
| 主锚点换了，但唯一的已绑定题干子块等仍在 | 仅在证据唯一且无冲突时转移绑定；保留旧锚点及依据 |
| 外部题目链接/题号一致 | 作为强匹配线索；同一道 LeetCode 可能有多个变式，不能仅靠题号合并 |
| 所有块重建或跨文档剪切粘贴 | 结合文本相似、旧块集合与来源迁移信息生成候选，交用户确认 |
| 拆一题为多题/多题合一 | 展示拆合预览；新子题使用独立 ID 并保留 lineage，旧作答仍留在旧题，不复制旧通过给全部新子题 |
| 匹配不确定 | 新候选不作为“历史新题”发布；旧题不自动判删；不合并练习历史 |

同次同步中来源 A 疑似少题、来源 B 出现相近新块时，先完成已登记来源的匹配检查，再确认删除候选。B 读取失败时，不能自动假定 A 中缺失的题不是迁移。对跨来源自动合并应保持保守。

顺序相反也一样：先同步目标文档 B、来源 A 还未同步或读取失败时，不能把相近迁入题立即发布为历史新题。跨来源比较使用本地已保存的全部绑定，只读取已登记来源，不扩大远端扫描范围。

已确认的旧题映射恢复后，首次练过时间、原始 question_id、评价和所有轮次连续保留。自动匹配应能解释是哪几个块或什么确认让它保持身份。

已知块生命周期限制：简单行内修改和移动通常保持 ID；整块替换、删除后重建、全文覆盖和复制可能改变 ID。因此不能承诺任意编辑都零人工保持身份，必须把歧义处理作为正常能力。

### 7.5 内容版本与复习依据

区分三个 ID：

| 概念 | 用途 |
|---|---|
| `question_id` | 同一道题跨时间、跨入口的身份 |
| `question_version_id` | 不可变题干、参考材料、分类及来源快照，供任务/作答引用 |
| `review_basis_id` | 本轮实际考察要求，用于判断不同版本的有效通过能否合计 |

版本差异不自动等于考察要求变化：

- 纯布局、位置、分类调整：保留依据 ID。只有实际数据变化才建新版本，无变化同步不生成重复版本。
- 明确是展示标题调整且独立题干没变：保留依据。若标题本身就是题干，则按题干变化检查。
- 题干或评分参考文本发生变化：展示差异；仅程序能明确识别的安全规范化变化直接沿用依据，不随意忽略数学符号、否定词或数值。
- 重要答案纠正、要求变化：新依据 ID。普通补充如果改变必须回答的要点，也按新依据处理。
- 错别字等语义等价修正可由模型建议，但不确定时默认不让旧通过证明新版；提供“仅文字修正，沿用依据”与“考察已变化”选择并留审计。无需用户重新导入题库。

实质变化后保持 question_id 和旧记录：旧达标显示“旧版已达标，新版尚未验证”。当前复习轮仍指向旧依据，用户可以明确继续旧版，或选择“按新版复习”。切到新版时旧轮记录为“因版本更替结束”，新轮从 0 开始；这是新考察依据的新一轮，旧次数完整保留并可查看，不清空整题历史。

“按新版复习”同时检查任务版本：已有未开始任务时，明确更新该任务内容并复用；已有进行中的旧版任务时，保留旧快照，按钮应说明将新增1个新版复习任务，再由该明确操作追加。允许这种用户主动选择的同题不同依据任务并存；它不放宽自动随机/自由练习的待办去重规则。新版任务开始时绑定新轮，旧版任务的迟到提交仍留在原依据。

**同步不自动给八股建轮或重新入库。**用户选择“按新版复习”即是明确入库授权，不重复确认。在用户决定前，新版日常作答可以保存，但不塞进旧版轮次进度。

代码的边界不同：若仍有旧依据活动轮，而用户在新版练习明确自评“不会做”，这次自评按代码自动入库规则结束旧依据轮并开新版轮，保留旧轮历史。触发者是新的不会做自评，不是同步；同题仍最多一个活动轮次。

### 7.6 来源删除与恢复

建议采用 `missing_pending` → `source_deleted` 两步：

1. 一次完整、无歧义的成功同步发现绑定题目不在来源中，标为疑似缺失，暂停后续普通抽取，保留全部记录。
2. 下一次独立完整读取仍确认缺失、且无未处理迁移/解析问题，才标“来源已删除”。同一后台任务重试不当作两次独立确认。用户也可在差异预览明确确认单题删除。
3. 整篇突然为空或出现大面积缺失，默认要求查看差异后确认；不能只靠一个删除比例阈值自动接受全量删除。
4. 权限不足、整个来源不可访问、网络失败、分页/依赖/解析不完整均为失败或不可用状态，不进入删除流程。
5. 被删题从普通每日/自由候选中排除，但既有任务、作答、轮次、反思引用保持。复习时展示来源已删除，用户决定继续或暂停；既有任务可继续快照，尚未开始的可明确取消，不能自动替换为另一题。
6. 同一来源锚点恢复时恢复可选状态并保持 question_id；重新出现但全部块已换时走匹配确认，不当作全新身份。

暂停复习、取消任务和来源停用都应有独立审计，不冒充达标。若提供取消任务，界面单独显示取消数；完成数不增加，既有基础目标不静默改写。

### 7.7 今天和正在答的题不被同步改变

- 基础任务创建时即记录一个版本；刷新不重抽。
- 开始作答时，服务端锁定该 task 的练习版本，创建 attempt；多标签进入同一任务会复用活动 attempt。
- 开始与“更新内容”并发时用条件更新/行版本号串行决策：开始成功后更新被拒绝，不能答到一半改变依据。
- 未开始任务显示“有新版本”；点击“更新本题内容”只修改其 `question_version_id`，question_id、任务 ID、配额和计数不变。
- 进行中或已完成任务永远保留原版本；想练新版需明确新练习。不会把原回答交给新答案重新评分后覆盖旧结果。
- 同步新增题不自动补今天缺额，也不增加目标；明确自由追加或“补齐缺额”才创建任务。

### 7.8 幂等与同步摘要

来源快照按 document_id、来源 revision、依赖版本集合及实际内容摘要去重；摘要用于判断内容是否相同，不用于题目永久身份。解析器升级应可复用快照并单独比较解析结果，不重新写作答。

相同内容同步只新增必要的运行日志，不增加题目、不可变题目版本、任务、attempt 或有效通过。禁止“每次同步 drop table 再重建”。

每次展示：新增已发布题数、更新题数、疑似缺失数、确认来源删除数、待确认/解析失败数、逐来源结果和最后成功时间。分类变更可单列，不能把失败题统计成删除题。

## 8. 数据模型和一致性约束

以下是逻辑实体分组，不强制把每项扩展成一套独立服务。使用 SQLite 外键、事务和必要唯一约束，避免用一份大聊天 JSON 作为唯一数据库。

| 实体 | 关键字段/关系 |
|---|---|
| Source / Dependency | 授权 URL、document_id、题型、身份、启用状态、依赖资源、检查/成功时间、错误 |
| SyncRun / SourceSnapshot | 运行状态、解析器版本、起止 revision、页清单、原始块与媒体清单、完整性证据、差异摘要 |
| Category | 本地 ID、来源标题块绑定、parent_id、当前名字、来源状态；不以文字路径作永久 ID |
| Question / SourceBinding | question_id、code/theory、feishu/derived、当前版本、来源状态、首个提交事实、经典星标、历史锚点 |
| QuestionVersion | 不可变题干、参考材料与来源性质、分类快照、媒体/Sheet 快照引用、review_basis_id、变化说明 |
| DailyPlan / Task | 用户时区和日期、基础目标/配额快照、task_id、question_id、选中版本、origin、基础或追加、完成/取消时间 |
| Attempt | task_id、question_version_id、开始时冻结的review_round_id（可空）、开始/提交时间、实际活动日期、进入方式、回答/自评/备注、答案暴露信息、请求幂等键 |
| Evaluation | attempt_id、模型原始结构化结果、说明与引用、模型/提示词/rubric 版本、状态、人工修正、当前采用结果 |
| ReviewRound / ReviewEvent | question_id、依据 ID、开始/结束原因、进入授权、达标/撤销事件、有效通过投影 |
| InterviewSession / Turn | 主任务、主问题版本、轮次、实际消息、追问来源、反馈、独立派生题引用 |
| Reflection | 日期、author=user/model、文本、版本、覆盖的 attempt/evaluation ID、生成时间、是否已过期 |
| ModelJob | job_id、业务幂等键、用途、状态、重试次数、错误、下一次可重试时间、结果引用 |

可把个人和模型反思放同表不同 author，但禁止模型更新 author=user 行。有效通过可以由 attempt + 采用评价 + 轮次 + 暴露事件计算，不必建立另一套可随意累加的事实；若缓存计数，必须能从源记录重建。

必须实现的约束：

- 每题同一时刻最多一个活动复习轮次，旧轮保留。
- 来源绑定活动主键唯一；重复来源/重复同步不会生成重复题。
- 同一日期仅一个基础计划；同一 task 仅有一个首次完成事实。
- 每个提交/追加命令有后端校验的幂等键；同键同载荷返回原结果，同键不同载荷报冲突。
- attempt 提交后内容不可覆写；“修改回答/再答”建立新 attempt，明确是否同任务重答。
- 每个 attempt 当前只采用一份评价；原始评价与修正历史都保存。慢返回的旧评价不能覆盖较新的人工采用结果。
- 有效通过受题目、轮次、自然日唯一性约束；相同 attempt 不重复算。
- 全部学习数据引用不可变 QuestionVersion；历史查询不得默认 JOIN 当前答案去覆盖旧依据。
- 所有外键关系禁止级联删除历史；删除来源不是删除 Question/Attempt。
- 模型调用和飞书读取无权直接更新任务目标、复习入库授权或个人反思。

### 8.1 时间与统计

时间戳存 UTC，归档日由后端统一按 `Asia/Shanghai` 计算并保存。`task.plan_date` 与 `attempt.activity_date` 分开：昨天的任务今天答，仍完成昨天计划里的任务，今天热力图显示实际练习活动；不自动迁移任务或创建副本。

今天页至少区分：基础目标、追加目标、已分配、已完成、缺额/取消。若跨日，另显示“今天实际练习”。完成计数按 task 的首次正式提交去重；通过次数与有效复习通过分开显示。

热力图默认强度为当日有真实提交的主任务数，按 `(activity_date, task_id)` 去重，区分代码/八股。昨天已完成任务今天再次实际作答，今天仍有活动，但不再次增加目标完成数；面试当天实际回答的追问也归到同一个主task，当天无论多少追问最多一个活动单位。仅打开页面或查看反馈不算活动。明细显示全部 attempt/turn；目标完成、当日活动、通过和有效复习通过分别统计。

### 8.2 关键事务

| 操作 | 同一个短事务中完成 |
|---|---|
| 生成/追加任务 | 核验幂等键、筛选去重、保存抽样结果、目标追加事实 |
| 提交代码自评 | 保存 attempt、首次完成任务、必要时开代码复习轮、更新通过投影 |
| 提交八股回答 | 保存 attempt、首次完成任务、建立待评价 job；此时不等模型 |
| 采用评价或人工修正 | 保存评价/修正、更新采用指针、重算受影响轮次及达标状态 |
| 八股明确入库 | 保存用户动作/指令依据、创建或复用活动轮次 |
| 发布来源变化 | 保存本来源快照和版本、更新绑定/当前指针/来源状态，绝不改学习事实 |

程序崩溃后，job 的运行租约到期可恢复为待重试。前端不应仅把作答保存在内存中等待模型成功；网络断开时明确提示尚未提交成功，允许以原幂等键重试。

## 9. 模型边界与接口契约

建立一个简单 `AgnesClient`，只暴露评价、解析自由请求、面试追问/整理、每日反思和有限解析辅助。采用普通 Chat Completions 请求，本地严格校验 JSON；首版不需要 tool calling，也不要求模型供应商支持 JSON Schema 强约束。

### 9.1 八股评价

输入必须包含题干版本、明确参考材料、材料来源与质量、用户原回答、评分规则版本。模型输出建议：

```text
verdict: aligned | needs_review | unable_to_assess
covered_points: [...]
missing_points: [...]
errors: [{claim, explanation, reference_ids}]
brief_feedback: ...
evidence_refs: [...]
```

`unable_to_assess` 是系统待核验，不是第三种用户自评。缺核心证据、答案冲突、输出截断、空内容或 JSON 校验失败，均不能默认按通过或不会处理。文档里的技术疑问不得当成可靠事实；参考不足时说明不足。

语义相同可以基本对齐；关键概念错误不能靠关键词覆盖。引用 ID 必须在输入白名单内，后端验证。评价不输出掌握度百分比，不自动加入复习。

测试集先用少量真实题构造：表达不同但正确、关键词齐但核心错误、明确缺要点、依据缺失、依据冲突、提示注入。期望结果由用户确认样例/人工审核建立，不能用同一个模型既生成标准又自证评分正确。

### 9.2 调用可靠性与安全

- 使用单并发持久化队列；建议优先级为当前练习评价/追问 > 自由请求 > 反思 > 解析辅助。超时和 429 不阻塞保存答案。
- 建议连接超时 10 秒、读取超时 90 秒；可重试网络错误、408、429、5xx，最多 3 次尝试，遵循服务端退避。401/403/不支持模型不盲目重试。
- 格式修复最多 1 次；仍失败置待评价。所有尝试属于同一个业务 job，不重复累计通过。
- 请求幂等键至少覆盖 attempt_id、question_version_id、rubric_version、prompt_version、model_id；主动重新评价建立新评价修订，不能覆写原文。
- 配置保存在后端环境变量或被 Git 忽略的本地配置。实施时仅迁移需要的字段，不 import 任意 Python 配置文件；日志不含密钥、认证头和整份个人题库。
- 浏览器不直接调用 Agnes 或 lark-cli。后端命令路径固定，参数按白名单构造 argv，`shell=False`，有超时及输出大小上限；模型不能拼终端命令。[Python subprocess 文档](https://docs.python.org/3/library/subprocess.html)
- 文档、答案、模型输出均当作不可信数据；提示词声明它们不是系统指令。网页对 HTML/Markdown 转义或净化，禁止渲染可执行脚本。
- 即使服务只在本机，也验证 Host/Origin，写操作使用基本 CSRF 防护；不用大型账号权限系统。
- 将来若增加代理 tool calls，发送上游前保证每个 `tool_calls[i].id` 非空；首版没有必要增加这个能力。

### 9.3 两份每日反思

个人反思独立编辑保存，模型没有覆写权限。模型反思从当天所有入口的真实 attempt、已采用评价、代码自评和面试 turn 读取证据，并保存覆盖 ID 集合、时间和生成版本。

生成后发生新作答、评价修正或新的面试反馈时，将旧反思标“尚未覆盖最新记录”，保留旧版并可重新生成。重新生成不改变个人反思、计划、经典星标和八股复习入库。

结论尽量关联到具体题目/作答；未看到代码只总结自评与备注，一次错误只称本次表现，不能推断长期缺陷或未练知识的掌握情况。

## 10. 存储、备份与建议项目结构

SQLite 存业务事实和快照索引，图片与较大的原始来源快照放应用数据目录，以内容摘要寻址并保留校验清单。快照不是临时下载目录：已经被任务、作答或反思引用的材料不能被清理。服务启动启用外键，采用短事务和有限并发；本地 schema 迁移必须有版本号和恢复步骤。

推荐每日首次数据变更后生成一次后台备份，保留最近 7 份日备份与少量周备份；迁移前额外备份。这是可调整的建议默认值。提供“导出全部学习数据”和“验证恢复”入口。

备份使用 SQLite backup API 生成一致性快照，不能在写入中只复制 `.db` 而漏掉 WAL。导出包包含数据库、被引用媒体、来源/版本清单和 schema 版本，不包含任何密钥。恢复应先在临时目录验证外键、记录数量和媒体摘要，再由明确恢复操作替换活动数据。[SQLite Backup API](https://sqlite.org/backup.html)

建议结构（实施草图，当前未创建这些业务文件）：

```text
learning-practice/
  AGENTS.md
  README.html
  pyproject.toml
  .gitignore
  app/
    main.py
    routes/
    services/         # tasks, practice, review, sync, reflection
    adapters/         # lark_cli, agnes
    parsers/          # block parsing and confirmed bindings
    storage/         # database access and migrations
    templates/
    static/
  tests/
    fixtures/        # small sanitized block/answer/failure cases
  data/             # ignored: database, source snapshots, media
  backups/          # ignored
```

函数默认不超过 40 行，文件以易读为先；验证、转换、I/O 和页面呈现分开。使用清楚的英文标识和初学者能看懂的注释，不为预想需求构建抽象框架。

## 11. 分阶段执行计划

不按页面先后交付，要按可验证闭环交付。每阶段结束提供演示步骤、实际检查结果、剩余限制和中文提交信息草稿。未获得 Git 提交授权时只给草稿。

| 阶段 | 交付内容 | 进入/退出条件 |
|---|---|---|
| P0 设计落定与接入小验证 | 确定独立项目目录/技术栈；确认 AGENTS/README 和 Git；验证 Agnes 2.5 当前免费调用；恢复图片/Sheet 必要读取；确认 2 个代码+3 个八股样例的拆题边界 | 图片题能显示原图，参考材料有版本依据；模型短请求及人工审核的样例可用。缺权限部分明确隔离，不能宣称整库完成 |
| P1 数据底座与持续同步 | schema、来源登记、原生分页、媒体/Sheet依赖、ID绑定、不可变版本、差异预览、按钮、缓存/失败状态、来源删除保护、备份骨架 | 增改移删/重复同步/分页失败通过；至少少量真实题可持续更新。没有这一阶段不能以一次性导入进入后续 |
| P2 今天与两类练习 | 总量/模块配额、随机稳定任务、代码自评、八股先保存后评价、幂等、基本任务历史、未开始任务更新版本 | 刷新不重抽，不会也完成；评价失败不丢回答；同步不改当天任务/正在回答的内容 |
| P3 复习完整闭环 | 八股手动入库、代码自动入库、轮次、每日有效去重/答案暴露、严格 >7天、退出/再次入库、评价纠错、版本变更提示 | 所有时间边界与版本依据用例通过；第一版基础学习闭环可日常使用 |
| P4 自由练习 | 自然语言主题数量、刷新检查、历史新题、随机追加、不足说明 | 5+3=8，历史做过/队列中/派生题排除；新增优化器题可被找到；失败明确基于缓存 |
| P5 秋招 | 薄弱/经典主问题、针对性追问、完整对话、结束、集中反馈、独立派生题整理与授权入库 | 2主问题各4追问只追加2；派生题有背景和来源；同步不能删派生题 |
| P6 反思与历史交付 | 个人/模型反思、证据引用与覆盖状态、热力图/时间线/题目历史、导出和恢复演练、界面完善 | 真实多入口数据演示，恢复后历史/版本/媒体一致；文档与运行方式完整 |

P0 的临时验收可以先使用可靠文本题走通模型，再补图题与表格；这只是并行推进方式，不能把题库中缺失媒体的核心问题从最终范围删除。

### 11.1 给多个执行 agent 的分工

先由协调 agent 冻结数据字段和业务契约。避免多个人同时修改 schema、任务计数和复习规则。

| 角色 | 文件/职责所有权 | 可并行时机 |
|---|---|---|
| 协调/数据 agent | storage、migrations、统一命令事务和关键规则 | P0/P1 先行；统一合并契约变化 |
| 来源同步 agent | adapters/lark_cli、parsers、services/sync、同步测试 | schema 与来源契约确定后 |
| 模型 agent | adapters/agnes、model jobs、评价契约与失败测试 | P0 可用假数据并行；不改复习入库逻辑 |
| 产品页面 agent | routes、templates、static、界面流程测试 | 业务接口固定后；页面不自行重算计数 |
| 验收 agent | 跨模块用例、时间边界、故障注入、恢复演练 | 随每阶段运行并检查实际结果 |

每个执行 agent 必须知道自己不是唯一编辑者，不能回退他人改动；遇到契约冲突交协调 agent 处理，不靠新增平行状态字段绕过。

## 12. 验收矩阵

这里列出的是**待实现后执行的验收**，本轮只完成文档/CLI读取调查，不声称以下软件测试已经通过。业务与时间测试使用可控时钟、固定候选夹具和 fake 模型，不必真的等待 7 天或依赖网络稳定。

### 12.1 用户明确要求的持续同步七场景

| ID | 操作 | 必须观察到的结果 |
|---|---|---|
| S01 | 飞书新增一道有明确题干的优化器题，完整同步后自由请求相关题 | 进入原题候选；历史无提交可被找到；抽取仍随机；今天原任务不变 |
| S02 | 已做题改标题/分类/顺序，保留原块；再模拟块全部重建 | 前者同 question_id 和历史；后者待匹配，不能冒充新题或丢历史 |
| S03 | 已做题补参考答案 | 新练习使用新版本；旧 attempt 仍能查看当时答案与评价依据；实质变化有提示 |
| S04 | 删除一道做过题并完成可信删除确认 | 普通选题不再抽到；题目历史、复习快照、反思引用仍可查看 |
| S05 | 网络失败、权限拒绝、返回空错误、第二页失败 | 原题库不被清空，不产生来源删除；缓存可练，显示失败和缓存时间 |
| S06 | 今天已有任务与完成记录时同步新增题 | 原任务 ID/题目/计数不变，无自动追加；只影响之后候选 |
| S07 | 相同内容多次同步/重试 | 题目、版本、作答、有效通过均不重复；可有多条同步运行日志 |

### 12.2 核心产品验收

| ID | 操作 | 预期 |
|---|---|---|
| B01 | 同候选池以多组固定随机种子生成新测试日；刷新同一天 | 跨种子抽样并非总取前 N；同一日列表稳定；同批无重复 |
| B02 | 只填八股总量；再填部分模块；再让模块和超过总量 | 前两种能生成；超额明确报错；父子重叠配额不能保存 |
| B03 | 模块不足/新分类/分类删除 | 不偷补固定配额，不自动改已存数量；显示缺口/新分类/失效配置 |
| B04 | 基础5，自由追加3 | 当天总目标8，基础5/追加3可分辨，未来默认不变 |
| B05 | 历史做过、仅打开、已在队列、模型失败已提交四题 | 自由池仅“仅打开且未在队列”可算历史新题 |
| B06 | 代码选不会；八股提交且模型判需复习 | 都完成一次；代码自动入库；八股没有明确动作不入库 |
| B07 | 模型超时、空响应、截断JSON、错误文本、401、429 | 回答先保存；待评价/退避明确；不误判不会，不重复完成 |
| B08 | 双击提交、两个页面提交同task、响应丢失后重试 | 一次首次完成、同业务请求复用结果；不同载荷冲突可解释 |
| B09 | 复习题已有待办/无待办；同任务重答 | 有则复用；无则追加1；重答保留attempt但不加任务 |
| B10 | 4次跨度10天；5次恰好604800秒；5次604801秒 | 前两种不退出，第三种退出；6次但跨度不足也不退出 |
| B11 | 同日多入口通过、提交前看答案、看答案后24小时内重答 | 所有记录保留，按规定最多1次或0次有效通过 |
| B12 | 累计4次后失败；已达标后再次不会 | 失败不清零；新一轮不继承旧5次；八股重新入库需明确动作 |
| B13 | 模型错误评价人工修正；修正已计数/已达标记录 | 原评价保留，采用值可追踪，重算进度/撤销依据；不自动八股再入库 |
| B14 | 实质改答案，旧轮4次；新版正常答对 | 同题身份，旧4次可看；新版不并入旧依据；明确切新版才开新轮 |
| B15 | 未开始任务更新版本；开始与更新并发 | 仅更新同题内容；已开始版本固定，冲突返回明确结果 |
| B16 | 2主问题，每题4次追问；无回答直接结束 | 前者只追加/完成2主任务；后者不完成；完整对话保留 |
| B17 | 整理一句依赖上下文的追问入库 | 补成独立题、保留背景/依据/来源，用户确认后入库；不多算任务 |
| B18 | 删除来源原题并同步，但存在面试派生题 | 原题历史保留，派生题不参与飞书删除判定 |
| B19 | 生成模型反思后新增作答/修正评价 | 旧模型反思标覆盖过期；个人反思原文不变；新反思可追溯覆盖集合 |
| B20 | 昨日任务今天完成；UTC日期与上海日期不同 | 计划归属不变，实际活动按上海今天归档，前后端一致 |
| B21 | 相同题不同入口练习 | 同 question_id 连续历史，各入口与任务来源保留 |
| B22 | 备份时有写入，导出并在临时目录恢复 | 外键和记录数一致，历史旧答案/媒体可读，密钥不在导出中 |
| B23 | 昨天完成任务，今天同任务实际重答或继续面试回答 | 今天热力图有活动；目标首次完成数不重复；同日多次回答只算一个主任务活动 |
| B24 | 作答绑定旧复习轮，评价延迟到新轮开启后才返回 | 只能回写旧attempt及其轮次证据，不给新轮加通过，也不复活已更替旧轮 |
| B25 | 正在做旧版任务时点击按新版复习；另测未开始旧任务 | 进行中的旧版本不动，明确追加新版1任务；未开始任务明确更新内容后复用，不重新随机 |

### 12.3 同步、模型和安全的必要故障用例

| ID | 故障或变化 | 预期 |
|---|---|---|
| F01 | >500块，题目在最后一页；第二页失败/游标循环/达到页上限 | 末页题可正常发现；异常不标完整成功、不删旧题 |
| F02 | 块树少一个子块、深层容器、未知块 | 检查覆盖并报告，不把未解析部分认成删题 |
| F03 | 分页中编辑源文档，前后revision不同 | 整批不发布；从头重试或保留缓存，不混用不同版本 |
| F04 | 图片失效/内嵌Sheet拒绝访问；父文档不变但Sheet更新 | 分别显示材料未覆盖；独立依赖检查能发现更新；不误称全库最新 |
| F05 | A成功B失败，或先同步迁入目标B而来源A未同步/失败 | 分来源安全发布；迁移歧义题不合并、不当新题、不确认删除 |
| F06 | 同题块复制、相同标题两题、原块删除重建、拆合题 | 保守匹配，人工决策可追溯；旧通过不复制到新子题 |
| F07 | 同步发布前崩溃/发布后响应丢失 | 原库或完整新事务可恢复，不出现半题/重复版本 |
| F08 | 升级解析器导致大量题目边界变化 | 先显示差异，不能直接重建题库或重置历史 |
| F09 | 模型返回不存在ID/提示注入/要求执行命令或自动入库 | 后端拒绝非法引用和越权动作；只按固定业务能力运行 |
| F10 | 较早模型job晚返回，用户已手动修正评价 | 原始结果可留存，不能覆盖用户当前采用结果 |
| F11 | 上次素材/分页失败后恢复条件但来源revision未变；已有missing_pending待确认 | 操作前检查仍重试未完成工作；下一次独立完整读取可推进删除确认，不被无变化快捷路径永久跳过 |

验收材料应包含实际操作步骤、数据库断言、页面截图或响应摘要、失败说明。随机机制测试使用固定测试种子保证可重复；不以随机抽一遍恰好不同来证明实现正确。真实远端文档的破坏性演练必须使用另行授权的测试来源，不能删改用户真实学习笔记来造场景。

## 13. 待定事项与启动条件

### 推荐方案已给出，不必重复询问硬约束

总量/配额、常规新旧题、主动复习追加、有效通过、历史新题时点、经典标记和异常处理，均按第5节默认设计。随机抽题、八股手动入库、累计5次且总跨度严格>7天、派生题隔离、持续同步均已明确，不再要求用户重选。

### 真正需要落定的少量事项

1. **纯笔记转题政策**：已提出推荐“明确题自动同步；纯笔记/复合题首次确认后入库”。当前未将用户尚未回复的选项视为确认。即使采用自动候选，也必须保留来源与待核验状态。
2. **部署默认**：本人电脑本地网页；若用户要求手机跨设备或公网，需重新设计访问方式和凭证存放，但不提前增加云端架构。
3. **实施接入门槛**：独立项目及 Git 按全局规则获准；原题图片与内嵌 Sheet 可读；Agnes 目标型号免费权益与短请求实测；确定初始解析样例。

这些事项不妨碍执行 agent 先阅读本文、设计测试夹具和整理阶段任务。不能跳过门槛后宣称整套题库已接通，不能把当前设计文档当作代码实施批准。

建议首个可审查里程碑：**用 2 道代码题、3 道八股题完成两次同步；中间模拟一次新增、一次答案变更，并保存一次失败练习与一次复习。证明题目身份、当天任务和旧评价依据都没有丢失。**
