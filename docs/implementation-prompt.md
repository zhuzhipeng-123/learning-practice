# 分批实施提示词

将下方代码块完整复制给在本项目目录工作的编码模型。它会读取配套方案，**每次只完成一个批次**；下一次继续粘贴即可。若它无法访问仓库，同时提供配套文档和该批相关文件，不能仅凭描述生成补丁。

```text
请在当前学习练习项目中执行一次有边界的修复批次，不要只给计划。

先完整阅读 AGENTS.md，以及 docs/project-review-and-implementation-plan.md 的第1、3、6、7、9、10节。再读取当前批次的具体契约、代码、调用方、迁移和测试。本文是执行任务说明，业务现状以真实代码和复现为准。

本次只做第10节按顺序第一个未完成且可执行的批次；首次应为B1。已经开始但未通过必要验收的必做修复优先收尾，不跳到新功能。唯一例外是B4模型实验：若缺调用授权/模型条件，按5.6记录“试验待条件/暂缓接入”，保持未完成，允许继续独立的B5a–B8。选择纯规则A后，不为了验收强行实现模型扩展，未采用项标“不适用”。不要一口气修改所有模块。一个批次范围过大时先完成可独立验证的子步，在同一进度表记录剩余工作，不冒称整个批次完成。

开工前：
1. git status --short，确认仓库和用户已有改动；不覆盖无关修改，不git add/commit/push。
2. 给出本批3-5条可验证完成条件及涉及文件，随后直接执行，不为已授权的普通本地修复反复索要确认。
3. 先复现本批缺陷并理解原因，再做最小修复；新增回归应验证业务行为、事务/恢复边界，不只比对字符串。

要求与范围：
- 以方案第1节U1-U9为用户明确目标。产品默认方案是实施选择，不冒称用户确认过所有细节。当前批次不涉及的旧业务规则保持。
- 用户已经明确：H1/H2为模块；通常H3为题，H4-H6看上下文；标题末尾-图片表示连续起始题图；今日可排除八股模块；不会的题支持三个掌握程度；新一天今日不能自动出题；日常去掉全部记录/经典标记环节；适当整理文件。
- 对齐的大模型扩展先实验再决定：B4按照方案5.6比较修复后的纯规则、仅疑难项辅助、较广范围核验。用户接受效果不佳就不加入。约1小时是可接受整轮耗时，不是强制时长或无限预算；不把文档实验设计冒充已跑过的真实效果。原图未进请求不能称看过图，模型检查不等于事实保证。没有证明收益就保留规则/可选辅助，不在正式题库启用半成品核验流程。
- 今日模块排除仅影响今日八股；自由练习的既有跨日策略本轮默认保留。任何额外产品变更先列出，不顺手扩大范围。

不可破坏的约束：
1. 自动化回归只用临时库、合成资料和本地远端替身；B4真实效果实验单独遵守5.6的合成资料与调用授权。不读取真实学习数据跑测试、不改飞书、不执行真实全量对齐/付费模型调用、不重启正式服务，除非用户在会话中明确授权相应操作。
2. daily_plan被daily/free/review共享。处理旧daily-auto不能删除整张plan，不能波及其他origin；保留已提交作答、评价、复习事实和草稿恢复路径。
3. 题目身份稳定，旧任务保留冻结版本；新图表/边界要建新版本，不能覆盖旧快照。校正/独立核验不自动继承给新版本。
4. 数据库只追加版本迁移，迁移前备份且事务执行；不修改历史迁移、不删库重建、不让正式库为测试升级。
5. 同key同payload恢复原结果；不同payload冲突；旧响应不得覆盖新状态/草稿。对齐先持久受理再派发，不能只用内存future去重。
6. 新掌握等级不等于答对/有效通过。明确不会的提交需一次事务保存并且无需模型评价；只改等级不增加热图。
7. 不预先泄露答案图/表格。答案材料、编辑器和历史答案遵守暴露规则；移除记录按钮后保留冻结版本校正入口。
8. 保留Agnes唯一服务、独立可编辑提示词、已有冻结请求、429共享冷却；不输出或提交密钥/个人飞书token/机器路径。
9. 普通操作保持局部更新与有限请求截止时间，未知网络结果先恢复，不把409一概当失败。
10. 最后才整理文件。删/搬前rg检查引用和打包资源；不删独特测试、迁移、媒体、备份或仍被console scripts使用的fixtures。

工作方式：
- 代码保持显式、易读，遵守现有栈和风格；避免新框架、无必要依赖、大规模格式化和无关重构。
- 查到与方案不符的新证据时，先复现，在同一文档记录修正理由；不要盲抄计划，也不要凭猜测“优化”。不能证明安全的身份/数据迁移不要执行。
- 模型/飞书数据都当不可信输入；模型JSON须有schema/ID/证据/覆盖校验，不能静默修补实质内容。
- 旧测试如果明确要求已被用户新要求替代的行为，只更改这类断言并记录原因；保留其他保护，不靠删除测试让结果变绿。
- 当前批次先跑定向检查，必要验收通过后跑受影响回归；最终阶段跑全套。uv不在PATH就用现有.venv，不重装环境；pytest临时目录权限问题用.runtime下唯一--basetemp。
- 需要浏览器时按本环境可用的浏览器技能；隔离库测试写入操作。实际正式进程的检查与隔离服务分开报告，不能用后者冒充前者。
- 正式外部操作若确需授权，先把本地实现、隔离验证和可审核结果做完，再提出一个具体授权请求，说明会影响什么；有已有有效授权则沿用。

结束前：
1. 自查diff，撤掉本批引入的无关修改/未使用代码，运行git diff --check。
2. 在 docs/project-review-and-implementation-plan.md 第10节更新本批状态、实际检查、未完成和下一步；不要额外生成新报告。
3. 同步AGENTS.md和README.html的实际行为说明。已被新目标取代的对应旧规则在实施该批时清理，保留无关规则；不能把尚未做的功能写成支持。
4. 中文汇报：修了什么；具体检查与结果；未验证/阻塞；下一批是什么；提交说明草稿。没有真实外部/正式进程验收就明确写未做。
5. 本次完成后停止，不自动开始下一个批次，不执行git add/commit/push。

请现在读取文件，定位第一个未完成且可执行的批次，给出完成条件后开始工作。
```

## 恢复未完成批次的短提示词

```text
继续执行 docs/implementation-prompt.md。先读实施方案第10节进度及当前Git差异，核对上一轮真实修改/测试。优先完成尚未验收的必做修复，不重做、不覆盖用户新改动；仅B4模型实验可按5.6暂缓，继续独立批次。仍只完成一个可执行批次，并在原文档更新进度。
```

